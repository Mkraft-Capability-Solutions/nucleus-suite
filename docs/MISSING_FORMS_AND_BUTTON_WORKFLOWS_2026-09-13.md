# Missing forms and button workflow audit

13 September 2026 | NucleusUI | Design and implementation handoff

The source audit identifies **23 missing form or setup destinations** behind active prototype controls, plus **7 incomplete actions where an input/review form is a proposed design choice**. Repeated buttons for the same workflow are grouped. There are also **15 existing or partially designed flows with incomplete capture/submission**, listed separately.

Scope: reviewed 553 button/clickable JSX elements across src/components, 18 literal form elements, named handlers, form/modal rendering and the active page imports. The 18 count excludes layouts built with inputs inside divs, such as the helpdesk form. This is a source-code audit, not browser execution or a check of off-repository design files. Counts are workflow groups, not percentage completion. Proposed fields below are implementation guidance, not a claim that each field is mandated by the product specifications.

## G Delivery guidance

1. Design the P0 forms first: employee creation, document upload, invitations, goals, off-cycle payroll, contractor registration, statutory filing, connector/API-key setup and identity recovery/enrollment.
2. Reuse existing components: ApprovalActionModal for leave remarks; existing project/leave/EWA forms for quick actions; existing letter preview and metadata for confirmation dispatch.
3. Each form ticket needs its F/P identifier, fields and defaults, validation, permissions, loading/error/success/cancel states, and the API contract. Each trigger must open the intended flow with the correct employee/record context.
4. QA acceptance: click opens the flow; input can be edited and validated; cancel makes no change; submit creates/updates once; real result is visible after reload. Do not display completion before the operation is confirmed.

Excluded from this missing-form count: disabled success/blocking status buttons; ordinary tab toggles; working local state transitions that need no extra input; and specification features with no button in the current code. A missing dedicated API is an integration gap and does not by itself mean a form is undesigned.
